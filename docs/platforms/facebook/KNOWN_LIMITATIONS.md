# Facebook Plugin — Known Limitations

1. **Private Photos / Friends-Only Media**: Requires active login permissions for the target user.
2. **Photo-Only Support**: `FacebookPlugin` intentionally declares `capabilities.media.video = false` (no video download filter). Video and Reel subtrees (`__typename: 'Video'`, `playable_url`, `profile_reel_node`) are skipped during GraphQL and DOM harvesting so Reel/video cover thumbnails do not leak as photo items.
3. **Current scan strategy**: media discovery navigates the profile's photo tabs (`photos_of`, `photos_by`, `photos_albums`, custom albums) with progressive scrolling and harvests rendered DOM photos plus embedded `application/json` payloads. Consequences:
   - The scan is **visible** in the tab (the page scrolls on its own). Do not switch tabs mid-scan.
   - The Comet Router navigation helper (`currentCometRouterInstance` / `CometRouter` via `window.require`) is a private, undocumented API and may break without notice; when it fails the scanner falls back to guarded DOM link clicks and the History API without allowing a full-page reload.
4. **GraphQL discovery**: the injected script no longer holds a `FETCH_FB_GRAPHQL`/`RESOLVE_FB_PHOTO` bridge — those handlers were dead (nothing dispatched them) and were removed. Photo discovery relies on in-page Comet navigation plus fetch/XHR response interception (`broadcastMediaBatch` → `fbProcessGraphQLText`) and DOM harvesting. Do not rely on GraphQL doc IDs for new features without capturing a fresh HAR first.
5. **Layout drift**: photo harvesting depends on `a[href*="/photo..."]` links and `img[src*="fbcdn.net"]`; a Facebook markup change can silently reduce yields. Zero-result scans on a page that visibly contains photos are the diagnostic signal.
6. **Max-resolution selection (signed CDN)**: a Facebook photo ships several signed CDN renders (`viewer_image`, `image`, optionally `images[]`), each protected by an HMAC (`oh`/`_nc_*`). `stp` and the CDN URL path can NEVER be rewritten without yielding HTTP 403, whereas a downscaled `ctp` CAN safely be replaced with `cstp` when `cstp` is present (`MetaCdn.upgradeUrl`). `FacebookNormalizer.selectBestRender` and `fbSelectBestRender` pick the largest signed render the payload provides (preferring `image` or `images[]` over a smaller `viewer_image`); if the only render returned is downscaled without a `cstp` hint, the original resolution is unreachable without a different capture.
