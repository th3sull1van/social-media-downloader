# Facebook Plugin — Known Limitations

1. **Private Photos / Friends-Only Media**: Requires active login permissions for the target user.
2. **Encrypted Video Streams**: Some Facebook Live or DRM-protected video streams are not supported for direct download.
3. **Scan strategy (since v1.1.0)**: media discovery navigates the profile's photo tabs (`photos_of`, `photos_by`, `photos_albums`, custom albums) with progressive scrolling and harvests rendered DOM photos plus embedded `application/json` payloads. Consequences:
   - The scan is **visible** in the tab (the page scrolls on its own). Do not switch tabs mid-scan.
   - The Comet Router navigation helper (`currentCometRouterInstance` / `CometRouter` via `window.require`) is a private, undocumented API and may break without notice; when it fails the scanner falls back to DOM link clicks and the History API.
4. **GraphQL doc IDs**: the `DOC_IDS.FB_*` constants in the injected script serve as documented GraphQL targets. The `FETCH_FB_GRAPHQL` bridge exists and works as transport, but photo discovery primarily uses in-page navigation and network interception. Do not trust those IDs for new features without capturing a fresh HAR first.
5. **Layout drift**: photo harvesting depends on `a[href*="/photo..."]` links and `img[src*="fbcdn.net"]`; a Facebook markup change can silently reduce yields. Zero-result scans on a page that visibly contains photos are the diagnostic signal.
6. **Max-resolution selection (signed CDN)**: a Facebook photo ships several signed CDN renders (`viewer_image`, `image`, optionally `images[]`), each with its own HMAC (`oh`/`_nc_*`). `FacebookNormalizer.selectBestRender` picks the largest render the payload provides rather than rewriting a `ctp` — rewriting a signed `ctp` invalidates the HMAC and returns HTTP 403. Therefore the downloader can only reach the resolution Facebook actually encoded in the payload; if the only render the page returned is already downscaled (e.g. `ctp < cstp` with no larger variant present), the full original is unreachable without a different capture (fixed 2026-08-28: previously `viewer_image` was taken first even when `image` carried a larger render).
